# intake (Предложка)

Внутренний Telegram-бот: принимает обращения сотрудников по работающим
сервисам, доводит их интервью до пригодного к работе описания и заводит тикет
в GitHub Issues нужного проекта.

Цель - убрать владельца из роли переводчика между сырым фидбеком и агентом.
Автор описывает проблему боту и получает номер тикета; владелец берёт тикет и
начинает спеку без единого уточняющего вопроса.

## Как это работает

1. Автор выбирает проект и нажимает «Создать тикет».
2. Накидывает контекст: текст, голосовые, скриншоты, ссылки. Бот копит и не
   перебивает.
3. Автор нажимает «Готово». Голосовые превращаются в транскрипт, затем
   скриншоты разбираются уже с учётом того, на что жалоба.
4. Бот добивает недостающее раундами по два-три вопроса, каждый с
   предполагаемым ответом. Кнопка «Всё так» принимает раунд целиком.
5. Бот показывает саммари и спрашивает, где ошибся. После подтверждения
   публикует issue и отдаёт номер и ссылку.
6. Файлы удаляются, в базе и в тикете остаётся текст и `file_id` Telegram.

## Стек

Go 1.25, PostgreSQL 16 (данные и очередь через `FOR UPDATE SKIP LOCKED`),
миграции goose, Telegram Bot API через `telebot.v4`, LLM через OpenRouter,
GitHub REST API. Runtime - один сервис в Docker, dev-контур в Coolify.

## Запуск

Кода пока нет. Команды появятся с первым срезом:

```sh
docker compose up -d postgres
make migrate-up
make run
make ci-check
```

Секреты передаются переменными окружения и в репозиторий не попадают:
токен Telegram-бота, ключ OpenRouter, GitHub PAT с правом Issues read/write,
белый список Telegram ID, строка подключения к базе.

## Ветки

`feature/<slug>` для среза, PR в `dev`; push в `dev` автодеплоится в
dev-контур; `main` релизная, обновляется release PR из `dev`. Прод только по
неизменяемому тегу и явной команде владельца.
