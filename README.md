# tg-intake (Предложка)

Внутренний Telegram-бот: единая точка входа бизнеса в разработку. Первая
версия принимает обращения сотрудников по работающим сервисам, доводит их
интервью до пригодного к работе описания и заводит тикет в GitHub Issues
нужного проекта.

Цель - убрать владельца из роли переводчика между сырым фидбеком и агентом.
Автор описывает проблему боту и получает номер тикета; владелец берёт тикет и
начинает спеку без единого уточняющего вопроса. Дальше тем же путём идут
движение тикета, заведение нового проекта через интервью и вопросы по
документации - порядок и границы в [docs/prd.md](docs/prd.md).

## Как это работает

1. Автор выбирает проект и нажимает «Создать тикет».
2. Накидывает контекст: текст, голосовые, скриншоты, ссылки. Бот копит и не
   перебивает.
3. Автор нажимает «Готово». Голосовые превращаются в транскрипт, затем
   скриншоты разбираются уже с учётом того, на что жалоба.
4. Бот добивает недостающее раундами по два-три вопроса, каждый с
   предполагаемым ответом. Кнопка «Всё так» принимает раунд целиком.
5. Бот показывает саммари и спрашивает, где ошибся. После подтверждения
   публикует issue и отдаёт номер и ссылку.
6. Файлы удаляются, в базе и в тикете остаётся текст и `file_id` Telegram.
7. Позже автор смотрит тикеты проекта командой `/tickets`: список со статусами,
   карточка с телом и последним комментарием, отмена своего тикета.

Новый проект заводится одним сообщением: `/project <ссылка на репозиторий>`.
Бот читает репозиторий сам и показывает, что получилось.

## Стек

Go 1.25, PostgreSQL 16 (данные и очередь через `FOR UPDATE SKIP LOCKED`),
миграции goose, Telegram Bot API через `telebot.v4`, LLM через OpenRouter,
GitHub REST API. Runtime - один сервис в Docker, контур в Coolify.

## Запуск

Всё из каталога `src`, переменные - в `.env` по образцу `.env.example`.

```sh
cp .env.example .env
docker compose up -d postgres
make migrate-up
make run
make ci-check
```

Секреты передаются переменными окружения и в репозиторий не попадают:
токен Telegram-бота, ключ OpenRouter, GitHub PAT с правом Issues read/write,
белый список Telegram ID, строка подключения к базе.

## Ветки и релизы

Ветка одна - `prod`. Срез делается в `feature/<slug>`, идёт PR в `prod` и
после мерджа удаляется. Деплой только по неизменяемому тегу `v*` и команде
владельца; автодеплоя по push нет. История версий - [CHANGELOG.md](CHANGELOG.md).
