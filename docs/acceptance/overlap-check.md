## Что меняется для людей

**Было.** Интервью шло только по репликам автора: контекст проекта у модели -
абзац, сочинённый из README при подключении. Тикет заводился одинаково и на
новое, и на выпущенное вчера. Из десяти обращений в `qualifier` с 14.08 четыре
пришли на уже сделанное: дубль активного тикета, работающая функция, требование,
закрытое релизом накануне. Каждое стоило захода триажа, а автор вместо новой
функции получал через несколько дней «оно уже работает».

**Стало.** Перед показом саммари бот сверяет черновик с тикетами репозитория и
документами состояния и показывает найденные пересечения со ссылками прямо в
карточке подтверждения. Решает автор: можно завести тикет всё равно, можно
бросить обращение «Сбросом». Заведённый тикет несёт раздел «Пересечения» - тот,
кто возьмёт его в работу, видит контекст сразу.

## Тех-сводка

- Шаг `overlap` в работе саммари: `GetRepo`, окно ленты issues в 100 записей и
  до четырёх документов (`CHANGELOG.md`, `README.md`, `docs/backlog.md`,
  `docs/architecture.md`) - те, что есть в репозитории. Дерево не запрашивается:
  отсутствующий файл отвечает 404.
- Свой бюджет 60 секунд, и на остатке работы шаг не начинается вовсе: иначе его
  повторы съедали бы время транзакции, которая показывает саммари.
- Вывод модели недоверенный: номер обязан быть среди выданных ей тикетов, путь -
  среди прочитанных файлов; заполненное разом, повтор источника и пустая заметка
  отбрасываются, заметка режется по 200 рун. Ссылки собирает Go, чужой заголовок
  чистится от скобок и адресов.
- Метка `author:` в модель не уходит: в ней ФИО сотрудника.
- Миграция `0010`: `cases.overlap`. Блок хранится markdown-ом, в чат идёт через
  `plainText`, в тело issue - как есть.

## Долги среза

- Сверка видит окно ленты в 100 записей вместе с pull request'ами: пересечение
  со старым тикетом активного репозитория останется незамеченным.
- Набор документов фиксирован. Проект с другой раскладкой сверяется только по
  тикетам и README.
- Каждая правка саммари сверяется заново: до шести запросов к GitHub и ход
  модели на круг, ничего между кругами не переиспользуется.
- Карта документов в промте описывает и те файлы, которых сверка не читает:
  модель может сослаться на них, и пункт отбросится как выдуманный.
- Дополнение существующего тикета комментарием (issue 32) не делается: исход
  один - новый тикет с разделом «Пересечения».
