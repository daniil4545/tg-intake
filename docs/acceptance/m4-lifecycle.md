# Приёмка M4: просмотр тикетов, отмена и подключение проектов

Дата: 2026-08-09. Срез: [plan-m4-lifecycle.md](../plans/plan-m4-lifecycle.md),
подключение проектов и команда `/project`. PR: `feature/m4-lifecycle`.

## Что меняется для людей

**Было.** Автор отправлял обращение, получал номер тикета и ссылку - и на этом
связь обрывалась. Узнать, взяли ли задачу в работу, он мог только написав
владельцу в личку. Ссылка помогала не всем: доступ к репозиториям есть у части
сотрудников.

**Стало.** Автор в любой момент открывает `/tickets`, выбирает проект и видит
последние тикеты со статусами по-русски. В карточке - текст тикета,
последний комментарий и ссылка. Свой тикет он может отменить, пока тот
не доигран; бот закрывает issue и подтверждает отмену сообщением. (Размер
страницы и состав карточки позже поменял срез M8, паспорт
[ticket-news.md](ticket-news.md).)

**Плюс.** Бот больше не показывает сотрудникам один себя. Новый проект
заводится одним сообщением: `/project <ссылка на репозиторий>` - бот сам читает
репозиторий и README, собирает название и описание и добавляет проект в меню без
выката и рестарта.

## Тех-сводка

Список строится из своей базы, статусы читаются у GitHub одним запросом в
момент открытия. Отмена идёт через очередь: ставит свою метку, точечно снимает
прочие метки статуса и закрывает issue как `not planned` - чужие метки при этом
целы. Статусы и их названия живут файлом правил, а не кодом, поэтому набор
правится без миграции. Просмотр ходит в GitHub отдельным клиентом с коротким
бюджетом: бот обрабатывает сообщения последовательно, и медленный ответ иначе
заморозил бы его для всех авторов.

## Как проверено

- Сборка, `go vet`, `gofmt` - чисто.
- `go test ./... -race` - зелёный, 44 теста.
- Миграция `0004` применяется и откатывается на живой базе, в том числе когда в
  очереди уже лежит работа отмены.
- Два ключевых теста проверены мутацией: со сломанным кодом они падают.
- Два независимых ревью полного PR: три блокирующих дефекта найдены,
  исправлены и покрыты тестами.
- 2026-08-09 - полное ревью проекта тремя агентами (модель и фундамент, путь
  автора, алгоритмы). Закрыто тем же днём: слова «Готово» и «Отмена» в
  разговоре больше не срабатывают как команды сбора, устаревшая кнопка «Начать
  заново» не стирает продвинутое обращение, контракт интервью копится между
  раундами, статусы тикетов вне окна сканирования добираются поштучно, поиск
  проекта не зависит от регистра, ход модели в `/project` ограничен бюджетом.
- Живого прогона в dev не было ни разу.

## Самопроверка на пять минут

`GITHUB_TOKEN` уже покрывает planerka и qualifier; для проекта вне этого списка
сначала расширить токен, иначе `/project` ответит отказом.

1. Напишите боту `/project https://github.com/daniil4545/planerka`. Ожидается
   карточка: название, репозиторий, абзац описания и строка о том, откуда он
   взялся. Проект появляется в `/start` без рестарта.
2. Напишите боту `/tickets` - он спросит, тикеты какого проекта показать. В
   списке должны быть все заведённые проекты.
3. Выберите проект. Ожидается список последних тикетов вида
   `#9 - Заведён - Заголовок`. Если тикетов нет, бот так и скажет.
4. Нажмите кнопку тикета. Ожидается карточка: номер, статус, автор, текст
   тикета, ссылка. Служебной строки вида `<!-- intake:case:... -->` в тексте
   быть не должно.
5. Поставьте в GitHub на этот issue метку `status:in-progress`, снимите
   `status:new` и переоткройте список. Статус должен стать «В работе».
6. Откройте карточку своего тикета и нажмите «Отменить тикет». Через несколько
   секунд придёт «Тикет #N отменён и закрыт». В GitHub issue закрыт как
   `not planned`, стоит `status:cancelled`, метки `type:` и `author:` целы.
7. Откройте карточку чужого тикета - кнопки «Отменить» быть не должно.

## Известные ограничения

- Уведомлений о смене статуса нет: автор узнаёт новости, только заглянув в
  бота. Отклонение может пролежать незамеченным - это срез M8.
- Комментарии автора к тикету не входят в срез, дополнить тикет можно только
  через GitHub - срез M9.
- Тикеты, заведённые в репозитории руками, боту не видны.
- Статусы списка читаются одним запросом по последней сотне issue; выпавшие из
  окна тикеты добираются поштучно, и при деградации GitHub часть списка
  покажет «статус недоступен». Точный статус всегда даёт карточка.
- Список ограничен последними тикетами проекта, поиска и фильтров нет.
- В репозиториях, заведённых до M4 (это один `tg-intake`), метка `status:new`
  осталась зелёной (`0e8a16`), а правила красят её серым: сервис существующие
  метки не перекрашивает. Чисто косметика, правится руками в GitHub.
- Полный набор меток в только что заведённом проекте появляется не сразу:
  команда ставит одну проверочную, остальные заводит ближайший старт или первая
  публикация.
- Выключить проект из бота нельзя: только через `PROJECTS` на чистой базе или
  правкой в базе.

## Как откатить

Выкатить предыдущий образ в Coolify и откатить миграцию: `goose down` до версии
`0003`. Откат снимает уникальный индекс и возвращает прежний список видов работ;
данные обращений и тикеты в GitHub он не трогает. Метки статусов, заведённые в
репозиториях, остаются - они безвредны и пригодятся при следующем выкате.
