# Приёмка: новости по тикету в боте

Дата: 2026-08-19. Спека: [plan-ticket-news.md](../plans/plan-ticket-news.md).
Ветка: `feature/ticket-news`, PR 35, релиз `v0.1.11`.

## Что меняется для людей

**Было.** Обмен по тикету жил в GitHub: смена статуса, разбор, комментарии
разработчика. Аккаунта GitHub нет ни у одного менеджера, поэтому до заказчика
работы не доходило ничего - он узнавал новости, только если сам открывал бота и
листал список. Список показывал десять последних тикетов проекта без листания,
карточка печатала полное описание, а последний комментарий - только у закрытых
тикетов.

**Стало.** Бот сам зовёт автора, когда тикет взяли в работу, отклонили, вывели в
прод или разработчик оставил комментарий. Сообщение короткое: факт и кнопка
перехода в карточку. В списке помечено, где есть новое; пометка гаснет, когда
автор открыл карточку. Карточка показывает краткое содержание и последний
комментарий у любого тикета, полное описание - по кнопке. Список листается по
десять, под ним выход в меню проекта и к проектам.

## Тех-сводка

- Четвёртая горутина `watch`: раз в пять минут два запроса на проект
  (`GET /issues?sort=updated`, `GET /issues/comments?since=`). Проект без
  тикетов запросов не тратит.
- Состав будящих статусов - поле `notify` в `rules/statuses.json`: правится без
  миграции и без выката.
- Миграция `0009`: `cases.told_status`, `told_comment_id`, `has_news`, `brief`,
  `projects.comments_since`.
- Инвариант «источник истины по статусу - метка issue» сохранён буквально:
  колонки статуса тикета нет, новые поля хранят факт доставки.
- Публикация проставляет `told_status` сразу; молчание первого наблюдения
  осталось только для тикетов, заведённых до миграции.
- Схема саммари получила `brief` (до 400 символов, через `scrubContacts`).

## Осталось проверить владельцу в боте

Экраны нажимаются в Telegram и агенту недоступны:

1. Пометка «новое» в списке тикетов и её гашение после открытия карточки.
2. Кнопки листания и выхода: «Предыдущие», «Следующие», «Меню проекта»,
   «К проектам», «К списку» из карточки.
3. Новый тикет целиком: краткое содержание в подтверждении саммари, тот же текст
   разделом «Кратко» в теле issue и в карточке.
4. Шум: не слишком ли частыми окажутся сообщения при десятке активных тикетов.

## Долги среза

- Ответить разработчику из бота нельзя: обратный канал (текст и голосовое)
  вынесен в следующий срез, он упирается в правило «одно активное обращение на
  автора».
- Тикеты, заведённые в репозитории руками, слежению не видны: список строится из
  `cases`.
- У тикетов до релиза краткого содержания нет: карточка показывает заголовок,
  статус и комментарий без описания.

## После приёмки

Первый заход владельца в бота 2026-08-19 дал две правки: полное тело тикета из
карточки убрано вместе с экраном «Подробнее» - оно занимало экран целиком и
вытесняло статус с комментарием; страница списка уменьшена с десяти тикетов до
пяти. Правки в контуре с того же дня, тега у них нет: владелец собирает
замечания, релиз перевыпускается одним номером, когда правки закончатся.
