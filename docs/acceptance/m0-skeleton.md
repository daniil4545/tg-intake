# Паспорт приёмки: M0, каркас сервиса

Спека - [plan-m0-skeleton.md](../plans/plan-m0-skeleton.md). Приёмка проходит в
dev-контуре; пункты, которые не требуют контура, проверяются локально.

## Что должно работать

Бот поднимается, узнаёт автора по белому списку, показывает список проектов из
базы и подтверждает выбор. Приёма обращений в срезе нет: это следующий срез.

## Проверки

| Что делаю | Что должен увидеть | Статус |
| --- | --- | --- |
| `make ci-check` локально | миграции применены, тесты, vet и build зелёные | пройдено 2026-08-08 |
| `docker compose up` в `src` | postgres healthy, `migrate` вышел с кодом 0, `app` healthy | пройдено 2026-08-08 |
| `/app healthcheck` при живой и мёртвой базе | код возврата 0 и 1 соответственно | пройдено 2026-08-08 |
| запуск бинаря с боевым токеном | в логе `starting`, `db_connected`, `bot_started` | пройдено 2026-08-08 |
| `kill -TERM` | в логе `shutdown`, процесс завершился | пройдено 2026-08-08 |
| `/start` от автора из белого списка | список проектов кнопками, в базе строка `users` | ждёт владельца |
| нажатие на проект | «Проект X выбран», в логе `project_selected` | ждёт владельца |
| `/start` от постороннего ID | отказ, в базе ни строки, в логе `access_denied` | ждёт владельца |
| сообщение боту в групповом чате | «Бот работает только в личной переписке» | ждёт владельца |
| чтение лога целиком | ни имени, ни username, ни текста сообщения | ждёт живого диалога |
| push в `dev` | образ `sha-<commit>` в GHCR, выкат Coolify, `app` healthy, версия в логе равна коммиту | ждёт сервиса Coolify |

## Что нужно от владельца

1. Telegram ID для белого списка: без него живые проверки не выполнить.
2. Сервис Coolify и три секрета репозитория: `COOLIFY_TOKEN`,
   `COOLIFY_API_BASE`, `COOLIFY_DEV_SERVICE_UUID`.

Один токен обслуживает один long-poller: локальный запуск и dev-контур
одновременно дают 409 Conflict. Живые проверки диалога и проверку деплоя ведём
по очереди либо заводим второго бота.
