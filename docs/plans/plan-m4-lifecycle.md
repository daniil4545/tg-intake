# Срез: просмотр тикетов, отмена и подключение проектов (M4)

Реализовано, релиз 0.1.0. Поток и статусы - `docs/architecture.md`, вызовы
GitHub - `docs/contracts.md`, правила статусов - `src/internal/app/rules/statuses.json`,
паспорт приёмки - [acceptance/m4-lifecycle.md](../acceptance/m4-lifecycle.md).
Здесь остаётся то, чего в них нет: что реализация решила иначе и почему.

## Отклонения при реализации

Приняты по ходу, каждое проверено ревью.

- `Tickets` держит `*Cases`, а не `pool`: иначе пришлось бы дублировать
  транзакционный хелпер `inTx`. Состоянием обращения по-прежнему владеет `Cases`.
- `NewGitHub` получил четвёртый параметр `statuses`: `PrepareProject` заводит
  метки статусов из правил, а взять их клиенту больше неоткуда.
- `Cancel` принимает проект и номер вместо готового `*Case`: бот и так резолвит
  проект, а обращение по паре ищет один запрос внутри.
- Начальная метка `status:new` тоже переехала в правила (`labelNew`). Она
  ставится публикацией из M2, и без этого набор статусов остался бы раздвоенным
  ровно в том месте, откуда его убирали.
- `LastComment` получил бюджет на всю операцию, а не на запрос: пять страниц по
  пять секунд заморозили бы бота на полминуты - то, от чего уходил быстрый клиент.
- Отмена не считает финальным собственный `status:cancelled` с прошлой попытки.
  Без этого повтор после падения между простановкой метки и закрытием issue
  решал бы, что тикет уже закрыт, и оставлял его открытым навсегда. Находка
  ревью, покрыта тестом.
- Статус тикета, вытесненного из окна сканирования (сотня последних номеров,
  включая pull request'ы), добирается поштучно быстрым клиентом; первый отказ
  останавливает добор. Находка ревью проекта 2026-08-09, покрыта тестом.
- Отмена пропавшего в GitHub тикета отвечает автору «тикета уже нет», а не
  завершает работу молча: автору обещано «сообщу, когда закроется». Находка
  того же ревью.

## Что осталось незакрытым

- Протокола причины отклонения нет: карточка честно показывает последний
  комментарий, а связать его с отказом можно будет только когда у владельца
  появится соглашение, как эту причину писать.
- Статус в списке ограничен окном в сто последних записей репозитория; точный
  статус даёт карточка.
