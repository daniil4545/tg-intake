## 3. Ведение диалога

Модель недетерминирована: тест идёт по её вопросам и проверяет инварианты исхода, не тексты.
- Шаг ждёт фейк до нового экрана раунда (кнопка `skip`) или саммари (кнопка `publish`):
  цикл с дедлайном 5 минут.
- Раунд: вопросы берутся из последнего `round_asked` (`questions[].key`). На каждый ключ
  сценарий даёт заготовку, на незнакомый ключ - «Не знаю». Ответ одним текстом автора.
- Саммари: «Публикую», затем ожидание статуса `published` и номера issue.
- Общие инварианты §2.1 после каждого шага: в фейке не больше одного сообщения с
  `inline_keyboard`; на каждое нажатие ровно один `answerCallbackQuery`.

события `case_events`, журнал фейка.

Во всех: метка `incomplete` и строка «Не уточнено:» есть тогда и только тогда, когда `gaps`
не пуст; заголовков модели (кроме «Кратко», «Ссылки», «Пересечения») от 1 до 6, без повторов.

Правки по итогам первого живого прогона (HEAD `425d06b`: S1, S5 pass; S2, S3, S4 fail без
поломки продукта, кроме `checkTurn`):
- S2: раунд проверяется только числом (не больше 1) - какой ключ спросит модель,
  недетерминировано; ключи вопросов идут в `t.Logf`, а не в жёсткую проверку.
- S3: `mixedR1Answers` дополнен ответом на `why`; раунд с вопросом по любому ключу ядра
  отвечается всеми заготовками ядра разом - модель спрашивала под одним ключом (`case`) то,
  что заготовлено под другим (`wrong`), и ответ строго по ключу конкретного вопроса терял бы
  эту идею.
- S4: `liveStepDeadline` - не меньше двух подряд попыток работы воркера (`2*jobTimeout` с
  запасом на паузу между ними), по-прежнему не позже `t.Deadline()` минус запас на `Cleanup`;
  таймаут цели `live` поднят до `3h`.
- Уровень лога live-прогона - `Info`, не `Warn`: разбор нуждается в `interview_round`
  (`gap_keys`) и `llm_call`, оба уровня `Info`.

Сценарий - подтест `t.Run`; итог - строка `t.Logf`: issue, метки, `kind`, `gaps`, события, pass/fail.
