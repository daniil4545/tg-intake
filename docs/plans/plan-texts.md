## 9. Решения среза

1. R9 - тест, а не grep §10: grep пропускает литералы не с буквы (`"## Кратко\n\n"`
   `github.go:659`, `alert.go:42`), ловит комментарии, зависит от локали; тест идёт в `make test`.
2. Одно правило для всех строк на русском, два файла вместо маркера: граница видна по имени
   файла, неизменность B - одной командой `git diff`.
3. B не правится: ввод модели меняет eval (Р-9), тело читают разработчики и
   `checkSummary`, описание уже созданной метки GitHub не обновится.
4. Два коммита: перенос проверяет машина, смысл правок - только чтение диффа стиля.
5. На `S1` тела функций дословно: дубли не объединяются, строки формата вводятся только на
   стиле и только в A. Иначе набор литералов §7, п.2 перестаёт доказывать перенос.
6. Уведомления владельцу - A: сообщение бота в чате.
7. Каталог - приложение: §11 просит дословный список, а строки срезов 5, 6 - после их кода.
8. «Токен», «Issues» в `/project` остаются: без них настройщик не поймёт, что чинить.
   «Статус» тикета - понятие автора, не «статус работы» §11.
