## Активные задачи

- [ ] **Расширять `GITHUB_TOKEN` при заведении проекта**: fine-grained PAT
      выдаётся на конкретные репозитории. Без права `/project` честно откажет.
      planerka и qualifier токеном уже покрыты (владелец, 2026-08-09).
- [ ] **Живость поллера в healthcheck**: telebot не отдаёт ошибки опроса,
      healthcheck проверяет базу; локальный поллер с тем же токеном молча
      забирает апдейты (`409 Conflict`), контур остаётся healthy. Там же -
      отдельный токен тестового бота в `.env.example`: один токен, один поллер.
- [ ] **Уведомление, исчерпавшее повторы, молчит навсегда**: у `HandleFailedJob`
      нет ветки `notify`, недоступность Telegram дольше минуты теряет вопрос
      раунда или номер тикета без следа для автора (ревью 2026-08-09).
- [ ] **`replaceJob` держится на конвенции**: DELETE без фильтра статуса может
      снять уже захваченную работу; корректность обеспечивают версионные
      проверки вызывающих. Сюда же гонка двойной отмены тикета: чинится
      транзакцией либо уникальным индексом `case_events(case_id, kind)`.
- [ ] **Скриншоты одного обращения разбираются одним job**: при деградации
      OpenRouter пачка не влезает в 4-минутный бюджет и уходит в повторы.
      Разбивать по элементу, как голосовые (ревью 2026-08-09). С 0.1.3 острее:
      попытка длится до двух минут, и один медленный скриншот оставляет
      следующие без бюджета; разобранное при этом остаётся `done`, повтор
      работы продолжает с оставшихся (ревью 2026-08-12).
- [ ] **Мелочи UX из прогона сценариев 2026-08-09**: окно 10 секунд после меню
      глотает осмысленное сообщение; «Продолжить» из чужого меню молча
      перенацеливает обращение; двойное «Всё так» отвечает про прошлый вопрос;
      карточка при недоступном GitHub предлагает отменить закрытый тикет;
      правка сообщения автором игнорируется.
- [ ] **Порог готовности зависит от формы обращения**: аккуратный текст
      проходит без вопросов, голосовое даёт раунд. Смотреть на обращениях
      заказчика; бедный тикет - поднимать планку промта.
- [ ] **Диалог перегружен сообщениями**: кандидаты на сжатие - сбор сразу после
      выбора проекта, протокол вместе с первым раундом. Решение владельца
      2026-08-08: смотреть на практике, пока не трогаем.
- [ ] **Golden-набор из реальных обращений**: подать боту исходное сырьё,
      сравнить тикет с написанным руками. Единственная проверка качества
      интервью и арбитр выбора моделей.
- [ ] **Один источник истины по формату ТЗ**: `plan-briefing.md` и шаблон PRD
      брифовщика описывают один артефакт по-разному. Свести до M6, вне этого
      репозитория.
- [ ] **Имя compose-проекта**: `name: intake` из-за совпадения каталога `src` у
      соседей; локальный 5432 занят - тестовый Postgres на своём порту.
- [ ] **Уборка очереди при следующей миграции `jobs`**: `'remind'` в CHECK не
      используется, таблица jobs не чистится, сканы по `payload->>'case_id'`
      без индекса. Заметно на порядки позже текущего масштаба.
- [ ] **Удалить механику «вопрос проекта внутри сбора»**: `askProject` из
      `CollectItem` стал защитой от старых данных; убрать вместе с
      `ErrNoProject`, когда живые прогоны подтвердят новый поток. Там же
      ловушка пустого списка проектов при активном обращении.
